# Как поселить бота на сервер

Локальный запуск через `start.sh` держится на твоём компьютере и туннеле
`trycloudflare`, у которого адрес меняется при каждом старте. Из-за этого
разосланные ссылки на вишлисты умирают, а бот живёт, пока не закрыт ноутбук.
На сервере адрес постоянный, и обе проблемы исчезают.

Проект уже к этому готов: есть `Dockerfile`, приложение слушает порт из
переменной `PORT`, само подхватывает свой публичный адрес и умеет работать с
Postgres. Отдельная сборка не нужна — хостинг строит образ сам.

## Railway (рекомендую — аккаунт уже есть)

1. **Создать сервис.** railway.app → *New Project* → *Deploy from GitHub repo* →
   репозиторий с этим ботом (ветка `main`).

   Railway увидит `Dockerfile` в корне и соберёт по нему. Ничего дополнительно
   указывать не нужно: *Root Directory* остаётся пустым.

3. **Добавить базу.** В проекте → *New* → *Database* → *PostgreSQL*.
   SQLite на хостинге не годится: контейнер пересоздаётся при каждом деплое и
   файл с данными пропадает вместе с ним.

4. **Прописать переменные** в сервисе бота (*Variables*):

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (ссылка на соседний сервис) |
   | `BOT_MODE` | `polling` |
   | `DEFAULT_CURRENCY` | `UAH` |

   `PUBLIC_URL` задавать не нужно: приложение возьмёт домен из
   `RAILWAY_PUBLIC_DOMAIN`, который Railway подставляет сам.

5. **Выдать домен.** *Settings* → *Networking* → *Generate Domain*.
   После этого нажать *Redeploy* — переменная с доменом появляется только
   вместе с ним, а адрес нужен приложению на старте.

6. **Проверить.** В логах должно быть:

   ```
   Бот @FamilyBoretsBot готов, режим polling
   Uvicorn running on http://0.0.0.0:8080
   ```

   Проверка здоровья: `https://<домен>/healthz` отдаёт `{"ok":true,...}`.
   В *Settings* → *Deploy* → *Healthcheck Path* можно указать `/healthz`,
   тогда Railway не будет считать деплой удачным, пока бот не поднялся.

7. **Кнопку меню в BotFather трогать не нужно** — бот при каждом старте сам
   ставит её на свой актуальный адрес.

## Что произойдёт с локальными данными

База на сервере стартует пустой. Списки и траты, которые уже заведены в
`family-bot/family.db` на компьютере, туда не переедут сами — их нужно
перелить отдельно (разово, скриптом, по внешнему адресу Postgres из вкладки
*Connect*). Если данных немного, проще завести заново.

## Локальный запуск после переезда

Он никуда не девается, но одновременно два бота с одним токеном работать не
могут: Telegram отдаёт апдейты только одному получателю, и они начнут драться
за очередь. Либо останавливай сервис на Railway, либо заведи для локальных
экспериментов отдельного бота у @BotFather.

## Свой VPS вместо Railway

Если захочется полного контроля, на сервере с Docker хватит:

```bash
git clone <адрес-репозитория> family-bot && cd family-bot
cp .env.example .env      # BOT_TOKEN и PUBLIC_URL с твоим доменом
docker compose up -d --build
```

`docker-compose.yml` кладёт SQLite в отдельный том, так что данные переживают
пересборку. Сверху нужен nginx с сертификатом (Telegram открывает
мини-приложение только по https).
